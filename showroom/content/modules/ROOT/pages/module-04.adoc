= Module 4: AMQ Applications Overview and Deployment

== Objectives

* See how messages move between the ACM hub and edge brokers
* Produce test messages on the hub (Mode 1: spoke brokers run on the hub)
* Optionally clone and compile the Java clients (not required for the ACM path)

== Application Overview

The demo includes four Java applications. You do **not** need to build or deploy them to complete this module. The required exercise uses the AMQ Broker image already on the cluster.

=== amqp-client (Quarkus Camel AMQP)

The primary producer/consumer used throughout the demo. Supports `mode=producer|consumer`, configurable `uri` and `address`.

=== mqtt-client (Quarkus Camel MQTT5)

Demonstrates multi-protocol edge messaging. MQTT messages land on the local broker and are forwarded via AMQP federation to the hub.

=== amqp-bridge (Camel AMQP)

A durable subscription bridge between source and target brokers. Stamps a `Pedigree` header on forwarded messages and drops messages whose pedigree matches the target to prevent federation loops.

=== artemis-extensions (StaticHeaderPlugin)

A broker-side plugin that injects configurable headers via the `beforeSend` hook. Deployed into the broker's classpath.

== Produce messages on the hub (required)

This is the path that demonstrates ACM hub and spoke messaging. Run it as `{user}` after xref:module-00.adoc[Module 0] login.

[source,bash,role=execute]
----
oc -n artemis run producer -ti \
  --image=registry.redhat.io/amq7/amq-broker-rhel8:7.12 \
  --rm=true --restart=Never -- /bin/bash
----

Inside the container:

[source,bash,subs="attributes+"]
----
/opt/amq/bin/artemis producer \
  --url=amqp://spoke-01-broker-amqp-acceptor-0-svc.artemis.svc.cluster.local:5672 \
  --protocol=AMQP --user={producer_user} --password={producer_password} \
  --message-count=10 --message='hello from NY edge' \
  --destination=topic://messages.NY.test --verbose
----

TIP: If Keycloak OIDC users (`{producer_user}`/`{producer_password}`) fail to authenticate with a SASL error, use the broker admin credentials (`admin`/`admin`) instead. The Keycloak realm import may need the user passwords to be set manually — see the deployment troubleshooting guide.

== Build the Java clients (optional)

Skip this section unless you want to compile the sample clients. It is not required to understand hub and spoke federation.

If you did not clone the repo in Module 0:

[source,bash]
----
git clone https://github.com/tosin2013/artemis-edge-acm-demo.git
cd artemis-edge-acm-demo
----

Point Maven at the writable PVC (see Module 0). `export HOME` alone is not enough: Java `user.home` is `/data`. Do not use `-Dquarkus.container-image.build=true` unless this terminal has podman or Docker.

[source,bash]
----
export HOME=/home/lab-user
export JAVA_TOOL_OPTIONS="-Duser.home=/home/lab-user"
export MAVEN_OPTS="-Dmaven.repo.local=/home/lab-user/.m2/repository"
mkdir -p /home/lab-user/.m2
cd java/amqp-client
mvn package -DskipTests
cd ../mqtt-client
mvn package -DskipTests
cd ../amqp-bridge
mvn package -DskipTests
----
