= Module 2: Provision SNOs and Observe ACM Edge Brokers

== Objectives

* Confirm SNO edge clusters are JOINED (provision with Hive only if they are missing)
* See RHACM Governance install AMQ on those SNOs (`edge-broker-policies`)
* Confirm `ztp-policies` stays unbound (no ApplicationSet children)

== Background

Hive (via RHACM) can provision SNO edge clusters on GCP. After a cluster joins with labels `sites: edge-sno` and `edge-region: NY|NJ|CT`, ACM ConfigurationPolicies in namespace `edge-broker-policies` install the AMQ Broker operator and one `ActiveMQArtemis` per region. Those SNO brokers federate to hub-01 over AMQPS.

The ApplicationSet `artemis-edge-workloads` in `ztp-policies` is *intentionally unbound*. Binding it would sync the full hub Helm chart to every SNO.

ifndef::mode_multi_hub[]
NOTE: Many Mode 1 environments already have `sno-edge-01` (NY) and `sno-edge-02` (NJ). If `oc get managedcluster` shows them JOINED, *do not* re-run `deploy-spokes.sh`. Skip to step 4.
endif::[]

ifdef::mode_multi_hub[]
NOTE: In Mode 2, spoke clusters may already be provisioned. Check their status before running the script.
endif::[]

== Steps

=== 1. Create GCP Credential in RHACM Console

Open the RHACM Console and create a cloud provider credential. This stores your GCP service account, pull secret, SSH keys, and base domain in a single ACM-managed secret.

[TIP]
====
RHACM Console URL: https://multicloud-console.{openshift_cluster_ingress_domain}
====

. Navigate to *Infrastructure -> Credentials -> Add credential*
. Select **Google Cloud Platform** as the provider type
. Set:
* **Credential name**: `gcp-credentials`
* **Namespace**: `gcp-credentials` (create new)
. Upload your **GCP service account JSON key** (or paste its contents)
. Enter your **Base DNS domain**: `{guid}.gcp.redhatworkshops.io`
. Paste your **Red Hat pull secret** (from https://console.redhat.com/openshift/install/pull-secret)
. Paste your **SSH public** and **private keys**
. Click **Add**

Verify the credential was created:

[source,bash,role=execute,subs="attributes+"]
----
oc get secret gcp-credentials -n gcp-credentials -o jsonpath='{.metadata.labels.cluster\.open-cluster-management\.io/type}'
----

.Expected output
[source,text]
----
gcp
----

=== 2. Run the Provisioning Script

The script extracts credentials from the ACM secret you just created and automates the entire Hive provisioning pipeline.

ifndef::mode_multi_hub[]
[source,bash,role=execute]
----
./scripts/deploy-spokes.sh --clusters 2
----
endif::[]

ifdef::mode_multi_hub[]
[source,bash,role=execute]
----
./scripts/deploy-spokes.sh --clusters 3
----
endif::[]

The script performs these steps automatically:

. **Pre-flight checks** — verifies `oc` login, Hive pods, ClusterImageSet, ArgoCD app
. **Credential extraction** — reads GCP key, pull secret, and SSH keys from the ACM credential (or bastion files)
. **Secret creation** — creates per-spoke namespaces with `gcp-creds`, `pull-secret`, and `ssh-private-key` secrets
. **ArgoCD patch** — enables `spokeProvisioning` in the Helm values, which creates:
** `ClusterDeployment` CRs (triggers Hive provisioning)
** `ManagedCluster` CRs (auto-imports clusters into RHACM)
** `KlusterletAddonConfig` CRs (enables ACM add-ons)
** RHACM Policies in `edge-broker-policies` (AMQ operator + per-region broker + federation)
. **Hive monitoring** — polls `ClusterDeployments` every 60 seconds until installed

=== 3. Monitor Provisioning Progress

While the script monitors automatically, you can also watch from a second terminal:

[source,bash,role=execute]
----
oc get clusterdeployments -A -o custom-columns=NAME:.metadata.name,INSTALLED:.spec.installed,PLATFORM:.spec.platform.gcp.region
----

Or use the watch flag for continuous updates:

[source,bash,role=execute]
----
oc get clusterdeployments -A -w
----

TIP: You can proceed to xref:module-03.adoc[Module 3: Verify AMQ Brokers and Federation] while the clusters provision. The spoke-specific AMQ brokers and federation will activate once the clusters join.

You can also check status at any time:

[source,bash,role=execute]
----
./scripts/deploy-spokes.sh --status
----

=== 5. Check Placement Decisions (edge-broker-policies)

AMQ on SNOs is selected by Placement in **`edge-broker-policies`**, not `ztp-policies`.

[source,bash,role=execute]
----
oc get placement -n edge-broker-policies
----

.Expected output
[source,text]
----
NAME                                       SUCCEEDED   REASON                    SELECTEDCLUSTERS
policy-amq-broker-operator-sno-placement   True        AllDecisionsScheduled     2
policy-amq-broker-spoke-01-placement       True        AllDecisionsScheduled     1
policy-amq-broker-spoke-02-placement       True        AllDecisionsScheduled     1
policy-amq-broker-spoke-03-placement       False       NoManagedClusterMatched
----

`spoke-03` (CT) stays unmatched unless a third SNO exists.

Confirm `ztp-policies` is **not** bound:

[source,bash,role=execute]
----
oc get placement -n ztp-policies
----

Those Placements show `NoManagedClusterSetBindings`. That is **expected**. Do not create a `ManagedClusterSetBinding` in `ztp-policies`.

=== 6. Verify RHACM Policies (AMQ on SNOs)

Open the RHACM Console → *Governance* → *Policies*, or run:

[source,bash,role=execute]
----
oc get policy -n edge-broker-policies
----

.Expected output
[source,text]
----
NAME                             REMEDIATION ACTION   COMPLIANCE STATE
policy-amq-broker-operator-sno   enforce              Compliant
policy-amq-broker-spoke-01       enforce              Compliant
policy-amq-broker-spoke-02       enforce              Compliant
policy-amq-broker-spoke-03       enforce
policy-block-spoke-01-federation  enforce
----

* `policy-amq-broker-operator-sno` — Namespace, OperatorGroup, and AMQ Broker Subscription on every `sites: edge-sno` cluster
* `policy-amq-broker-spoke-01` / `spoke-02` — one `ActiveMQArtemis` per region, with AMQP federation to hub-01
* `policy-block-spoke-01-federation` — stays **disabled** until xref:module-06.adoc[Module 6]

See which clusters each broker policy hit:

[source,bash,role=execute]
----
oc get policy policy-amq-broker-spoke-01 -n edge-broker-policies -o jsonpath='{range .status.status[*]}{.clustername} {.compliant}{"\n"}{end}'
----

.Expected output
[source,text]
----
sno-edge-01 Compliant
----

You cannot `oc login` to the SNOs as `{user}`. Policy status on the hub is how you confirm AMQ landed on the edge.

=== 7. Troubleshooting

If a cluster is stuck provisioning, check the ClusterDeployment conditions:

[source,bash,role=execute]
----
oc get clusterdeployment sno-edge-01 -n sno-edge-01 -o yaml | grep -A 10 conditions
----

Check the provisioning pod logs:

[source,bash,role=execute]
----
oc logs -n sno-edge-01 -l hive.openshift.io/cluster-deployment-name=sno-edge-01 --tail=50
----

Common issues:

* **GCP quota exceeded** — ensure n2-standard-8 vCPU quota allows concurrent SNO installs (8 vCPUs per cluster)
* **DNS zone not found** — verify the base domain matches your GCP sandbox DNS zone
* **Credential error** — re-check the GCP service account JSON in the RHACM credential

To tear down spoke clusters and start over:

[source,bash,role=execute]
----
./scripts/destroy-spokes.sh
----
