= Module 5: Produce and Consume Messages

== Objectives

* Send messages from SNO edge brokers using regional addresses
* Consume those messages at hub-01 (federation)
* Confirm hub-colocated `spoke-*` URLs are not this exercise

== Steps

=== 1. Start a Consumer on the Hub

IMPORTANT: Start the consumer *before* producing messages. Topic (multicast) subscriptions only receive messages sent after the subscription is created.

Open a terminal and run:

[source,bash,role=execute]
----
oc -n artemis run consumer -ti \
  --image=registry.redhat.io/amq7/amq-broker-rhel8:7.12 \
  --rm=true --restart=Never -- /bin/bash
----

Inside the container:

[source,bash,subs="attributes+"]
----
/opt/amq/bin/artemis consumer \
  --url=amqp://hub-01-broker-amqp-acceptor-0-svc.artemis.svc.cluster.local:5672 \
  --protocol=AMQP --user={consumer_user} --password={consumer_password} \
  --destination=topic://messages.NY.test --message-count=5 --receive-timeout=60000 --verbose
----

TIP: If `{consumer_user}`/`{consumer_password}` fails with a SASL authentication error, use `admin`/`admin` instead.

Leave this consumer running and open a *second terminal* for the next step.

=== 2. Produce from the NY SNO

Use the sno-edge-01 AMQPS Route. SNO brokers use `admin` / `admin`.

[source,bash,subs="attributes+"]
----
oc -n artemis run producer-ny -ti \
  --image=registry.redhat.io/amq7/amq-broker-rhel8:7.12 \
  --rm=true --restart=Never -- /opt/amq/bin/artemis producer \
  --url='amqps://spoke-01-broker-amqps-acceptor-0-svc-rte-artemis.apps.sno-edge-01.{guid}.gcp.redhatworkshops.io:443?sslEnabled=true&transport.trustAll=true&transport.verifyHost=false&useTopologyForLoadBalancing=false' \
  --protocol=AMQP --user=admin --password=admin \
  --message-count=5 --message='hello from NY SNO' \
  --destination=topic://messages.NY.test --verbose
----

The hub consumer should receive the five `messages.NY.test` messages.

=== 3. Produce from the NJ SNO

[source,bash,subs="attributes+"]
----
oc -n artemis run producer-nj -ti \
  --image=registry.redhat.io/amq7/amq-broker-rhel8:7.12 \
  --rm=true --restart=Never -- /opt/amq/bin/artemis producer \
  --url='amqps://spoke-02-broker-amqps-acceptor-0-svc-rte-artemis.apps.sno-edge-02.{guid}.gcp.redhatworkshops.io:443?sslEnabled=true&transport.trustAll=true&transport.verifyHost=false&useTopologyForLoadBalancing=false' \
  --protocol=AMQP --user=admin --password=admin \
  --message-count=5 --message='hello from NJ SNO' \
  --destination=topic://messages.NJ.test --verbose
----

Start a hub consumer on `topic://messages.NJ.test` first if you want to see these arrive. The SNO remote address policy *pushes* `messages.{region}.#` to hub-01. `messages.ALL.#` is pulled from the hub onto the SNO, not the reverse.

=== 4. CT region

This catalog item often has no `sno-edge-03`. `policy-amq-broker-spoke-03` stays unmatched. Skip CT unless Module 2 showed a CT SNO.

NOTE: The `artemis` CLI does not support `--protocol=MQTT`. Native MQTT would target the SNO MQTT acceptor, which is not exposed on a Route in this demo.
