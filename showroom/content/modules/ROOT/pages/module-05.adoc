= Module 5: Produce and Consume Messages

== Objectives

* Send messages from SNO edge brokers using regional addresses
* Consume those messages at hub-01 (federation)
* Confirm hub-colocated `spoke-*` URLs are not this exercise

ifdef::mode_multi_hub[]
Hub-01 in these steps is the **AMQ hub on this regional ACM hub**, not Global Hub. `messages.NY.5604` should appear on hub-01; `messages.NY.5603` must not.

.Mode 2 messaging — 5604 reaches AMQ hub-01; 5603 stays on the SNO
image::mode2-amq-federation.png[NY and NJ site brokers federate over AMQPS to AMQ hub-01 on regional ACM east. messages.NY.5604 reaches the AMQ hub; messages.NY.5603 stays on the SNO. Global Hub has no AMQ broker.,link=self,window=blank,width=800]
endif::[]

== Steps

=== 1. Start a Consumer on the Hub

IMPORTANT: Start the consumer *before* producing messages. Topic (multicast) subscriptions only receive messages sent after the subscription is created.

Open a terminal and run:

[source,bash,role=execute]
----
oc -n artemis run consumer -ti \
  --image=registry.redhat.io/amq7/amq-broker-rhel8:7.12 \
  --rm=true --restart=Never -- /bin/bash
----

Inside the container:

ifndef::mode_multi_hub[]
[source,bash,subs="attributes+"]
----
/opt/amq/bin/artemis consumer \
  --url=amqp://hub-01-broker-amqp-acceptor-0-svc.artemis.svc.cluster.local:5672 \
  --protocol=AMQP --user={consumer_user} --password={consumer_password} \
  --destination=topic://messages.NY.test --message-count=5 --receive-timeout=60000 --verbose
----
endif::[]

ifdef::mode_multi_hub[]
[source,bash,subs="attributes+"]
----
/opt/amq/bin/artemis consumer \
  --url=amqp://hub-01-broker-amqp-acceptor-0-svc.artemis.svc.cluster.local:5672 \
  --protocol=AMQP --user={consumer_user} --password={consumer_password} \
  --destination=topic://messages.NY.5604 --message-count=5 --receive-timeout=60000 --verbose
----
endif::[]

TIP: If `{consumer_user}`/`{consumer_password}` fails with a SASL authentication error, use `admin`/`admin` instead.

Leave this consumer running and open a *second terminal* for the next step. After the NY producer finishes, the consumer prints five `Received` lines and `Consumed: 5 messages`. JMS Message IDs and elapsed time differ every run.

=== 3. Prove 5603 stays on the SNO

Start a **new** hub consumer on `topic://messages.NY.5603`, then produce that address on the NY SNO. The hub consumer must print **no** `Received` lines (`Consumed: 0 messages` after the timeout). `messages.*.5603` is excluded from both local and remote federation.

[source,bash,subs="attributes+"]
----
oc -n artemis run consumer-5603 -ti \
  --image=registry.redhat.io/amq7/amq-broker-rhel8:7.12 \
  --rm=true --restart=Never -- /opt/amq/bin/artemis consumer \
  --url=amqp://hub-01-broker-amqp-acceptor-0-svc.artemis.svc.cluster.local:5672 \
  --protocol=AMQP --user={consumer_user} --password={consumer_password} \
  --destination=topic://messages.NY.5603 --message-count=5 --receive-timeout=15000 --verbose
----

In a second terminal, produce while that consumer is waiting:

[source,bash,subs="attributes+"]
----
oc -n artemis run producer-5603 -ti \
  --image=registry.redhat.io/amq7/amq-broker-rhel8:7.12 \
  --rm=true --restart=Never -- /opt/amq/bin/artemis producer \
  --url='amqps://spoke-01-broker-amqps-acceptor-0-svc-rte-artemis.apps.sno-edge-01.{guid}.gcp.redhatworkshops.io:443?sslEnabled=true&transport.trustAll=true&transport.verifyHost=false&useTopologyForLoadBalancing=false' \
  --protocol=AMQP --user=admin --password=admin \
  --message-count=5 --message='stays on NY SNO' \
  --destination=topic://messages.NY.5603 --verbose
----

.Expected output (hub consumer — nothing arrives)
[source,text]
----
Consumer messages.NY.5603, thread=0 Consumed: 0 messages
----

The 5604 consumer from step 1 also receives **nothing** from this produce — 5603 is a different address and is excluded from federation.
endif::[]
